# Spec: copyfail-defense v2.1.1 — io_uring auto-detect with layered suppression

## 1. Goal

Promote `kernel.io_uring_disabled = 2` from "commented-out operator opt-in"
(shipped in v2.1.0) to **auto-applied with layered suppression**, matching
the policy used by every other host-altering primitive in the package.

The driver is consistency: v2.1.0 ships modprobe blacklists, systemd
RestrictAddressFamilies tokens, audit rules, and userns sysctls that are
*all* gated on workload auto-detect. Only `io_uring_disabled` was
shipped as a static, commented opt-in — inconsistent with the rest of
the policy and a missed mitigation on the bare-host case.

## 2. Non-goals

- Renaming the project to `rfxn-defense` (still deferred).
- Changing the bug-class taxonomy (`pintheft` / `keysign-pwn` remain
  the v2.1.0 entries).
- Adding io_uring runtime instrumentation (eBPF, audit syscall trace).
  The auto-detect is signature-based and runs once at %posttrans plus
  on operator-invoked redetect.
- Live blocking of io_uring on running workloads. The sysctl applies
  to *new* processes via `=2` (hard-disable); existing tasks holding
  io_uring fds are unaffected until restart. Operator must orchestrate
  restarts of consumers if they want full disable on a live host.

## 3. Architecture decisions

### 3.1 Two-file sysctl split

Today `packaging/copyfail-sysctl-userns.conf` mixes three concerns
(userns max, ptrace_scope, io_uring) in one drop file. Suppression
is binary at the file level — the whole file is dropped or not. That
collapses the layering we want: a host where `userns_consumers` are
absent (apply userns + ptrace_scope) but io_uring workload IS present
(suppress io_uring only) cannot be expressed.

**Decision:** split into two files at /etc/sysctl.d/:
- `99-copyfail-defense-userns.conf` — userns keys + ptrace_scope
  (suppression unchanged: rootless OR userns_consumers)
- `99-copyfail-defense-iouring.conf` — only `kernel.io_uring_disabled = 2`
  (suppression: rootless OR userns_consumers OR io_uring_workload OR kernel<6.6)

Two separate apply/teardown handles; two separate JSON state entries.

### 3.2 io_uring workload signals

`detect_io_uring_workload()` runs OR over five signals (any one trips):

1. **liburing.so* in any /proc/*/maps** — strongest signal that
   a running process is using io_uring. Walked with bounded glob
   `/proc/[0-9]*/maps` to avoid /proc/self issues; grep `liburing\.so`
   on each (silent on permission denied for non-root mounts).
2. **Known consumer binary list present and executable** — `/usr/bin/`
   and `/usr/sbin/` paths for: postgres (>=16, but we can't easily
   version-gate so we treat any postgres as a signal; postgres <16 with
   `io_method=worker` doesn't use io_uring but the false-positive cost
   is low — the operator keeps io_uring), scylla, mariadbd-ge,
   dockerd (uses for some storage drivers), redis-server, nginx,
   envoy, rabbitmq-server.
3. **systemd unit `io_uring`-named** — best-effort; some workloads
   ship a service named with the substring.
4. **/proc/sys/kernel/io_uring_disabled already set non-zero** —
   weak signal that an operator has explicitly tuned this; respect.
5. **CONFIG_IO_URING not present in /boot/config-$(uname -r)** —
   kernel built without io_uring; key would be a no-op. Treat as
   "workload absent" (no need to suppress).

Signal 1 is canonical. Signals 2-3 are heuristic adjuncts. Signals
4-5 are tie-breakers — non-trivial to expose via the standard signal
array because they don't represent "workload present", but they're
mentioned in the planning challenge for completeness. Implementation
will keep the same shape as the other detectors: array of strings
captured per signal that fired.

### 3.3 Kernel version gate

io_uring sysctl key (`kernel.io_uring_disabled`) requires Linux 6.6+.
Earlier kernels silently ignore the key (the `-` prefix in sysctl.d
already handles this safely), but we still gate explicitly so the
JSON state can report `suppressed.io_uring_disable.reason = "kernel_too_old"`.

Detection: `uname -r` parse, leftmost `MAJOR.MINOR` compared
numerically against `6.6`. Beware RHEL backports — they don't change
`uname -r` upstream version, so kernel 5.14 on EL9 stays at 5.14
even with io_uring backported. We accept this false-suppression
(io_uring may work but we don't apply our cut). Operator can use
`CFD_FORCE_IOURING_DISABLE=1` to override.

### 3.4 Operator override knobs

Symmetric to existing detectors:

- `/etc/copyfail/force-full` — existing all-mitigations override
  (already applies; no change).
- `CFD_FORCE_IOURING_DISABLE=1` env — force-apply even if signals fire.
- `CFD_SUPPRESS_IOURING_DISABLE=1` env — force-suppress even on clean host.

These are env vars read at `detect.sh` invocation; passed through
from %posttrans via systemd-style `Environment=` is out of scope —
operator runs `CFD_FORCE_IOURING_DISABLE=1 copyfail-redetect` if needed.

### 3.5 Failure mode asymmetry (operator memory)

Suppression criteria for io_uring are *broader* than userns by
design. The asymmetry is intentional:

- **userns false-suppress** = rootless podman keeps working;
  cf2/Fragnesia chain reachable on this host. Loss: defense in depth.
- **userns false-apply** = rootless podman / Flatpak fails LOUDLY at
  next launch ("user_namespaces creation forbidden").
- **io_uring false-suppress** = io_uring stays enabled; PinTheft
  secondary mitigation skipped. Loss: defense in depth on Linux 6.6+.
- **io_uring false-apply** = io_uring consumer SILENTLY stalls / falls
  back to slow path / hangs at io_uring_setup(2) returning -EPERM.

The silent-stall case is operationally worse than userns false-apply.
Hence layered suppression biases toward not-applying. Operator
escape hatch is the env var above.

## 7. Risks + mitigations

| Risk | Mitigation |
|------|------------|
| liburing.so* glob misses statically linked io_uring users (Go, Rust) | Add binary name list as secondary signal; document in README that detection is best-effort |
| Process loads liburing AFTER apply (race) | Operator runs `copyfail-redetect` post-deployment-rollout; document this |
| kernel <6.6 detection fails on RHEL backport kernels | Operator env override; document explicitly in README |
| gh-pages archive move breaks deep links | Keep file paths under `/archive/` mirroring original; update copyfail.repo doc text only if needed |
| Live canary fails on one EL after publish | HARD blocker; reroll publish |
| io_uring detector adds 100ms+ to %posttrans on busy hosts | Bound to /proc/[0-9]*/maps glob, no recursive find, no /proc/self |

## 8. Operator override matrix (final state)

| Override | Mechanism | Effect |
|----------|-----------|--------|
| Skip all detection | `/etc/copyfail/force-full` sentinel | apply everything |
| Force io_uring suppress | `CFD_SUPPRESS_IOURING_DISABLE=1` env | suppress regardless of detection |
| Force io_uring apply | `CFD_FORCE_IOURING_DISABLE=1` env | apply regardless of detection |
| Per-host higher-priority sysctl | drop a `50-*.conf` with higher value in /etc/sysctl.d/ | sysctl.d lexicographic merge |

## 9. Edge cases

1. **Bare EL10 host, no detected workload, kernel 6.6+** —
   io_uring key applied to /etc/sysctl.d/99-copyfail-defense-iouring.conf.
   Expected: `applied.sysctl_iouring=true`.
2. **EL10 host with postgres binary present but not running** —
   binary list signal fires. Suppressed with reason `io_uring_workload`.
3. **EL10 host with postgres NOT installed but running container that
   uses io_uring inside** — host /proc/*/maps shows liburing.so from the
   container PID (namespaced visible to root). Signal 1 fires.
   Suppressed.
4. **EL9 host (kernel 5.14, no backport)** — kernel gate fires.
   Suppressed with reason `kernel_too_old`.
5. **EL7 host (kernel 3.10)** — kernel gate fires. Suppressed.
6. **Operator hand-edits 99-copyfail-defense-iouring.conf** — cmp-and-skip
   preserves operator edits per D-57 (existing pattern).
7. **/etc/copyfail/force-full present + io_uring_workload detected** —
   force-full wins (operator override beats detection). Apply.
8. **CFD_SUPPRESS_IOURING_DISABLE=1 + force-full both set** — force-full
   wins (apply). Rationale: force-full is the global operator override
   ("override every auto-detect decision; trust me, apply everything"),
   and `decide_suppressions()` returns immediately on force-full BEFORE
   reading the env knob. If an operator wants finer-grained override,
   they should NOT set force-full alongside the env suppress. Documented
   in README §Operator override.

## 10. Decision: gh-pages archival policy

Operator memory `project_v2_1_0_shipped` plan-conventions block says
"v2.0.x RPMs stay in gh-pages tree (docs-only cleanup; never delete
published artifacts)". New operator instruction says "only showing
the latest rpm's". These reconcile via subtree move:

- Old RPMs (2.0.0, 2.0.1-2, 2.0.2, 2.1.0) move from
  `gh-pages:repo/{EL}/x86_64/*.rpm` to
  `gh-pages:repo/{EL}/x86_64/archive/*.rpm`. URLs change but the file
  stays reachable; we update `gh-pages:repo/{EL}/x86_64/archive/index.html`
  with a manifest.
- Top-level `repo/{EL}/x86_64/` then contains only v2.1.1 RPMs +
  fresh repodata + fresh index.html.
- `dnf install copyfail-defense` against the published repo resolves
  v2.1.1 exclusively.
