# Implementation Plan: copyfail-defense v2.1.0 — PinTheft + ssh-keysign-pwn coverage + EL7

**Goal:** Ship v2.1.0 of copyfail-defense (NO rename — that's deferred). Add PinTheft (RDS + io_uring) coverage, add CVE-2026-46333 ssh-keysign-pwn (ptrace exit-race) coverage, extend build matrix to EL7. Bug-class taxonomy gains `pintheft` (Copy Fail class) and `keysign-pwn` (FD-theft class) without disrupting the existing 4 classes.

**Architecture:** Defense primitives unchanged in shape — modprobe blacklists, systemd `RestrictAddressFamilies`, sysctl drop-ins, auditd tripwires, LD_PRELOAD shim. Extended with three new entry-point cuts:
1. `rds`/`rds_tcp`/`rds_rdma` modprobe blacklist (PinTheft)
2. `kernel.yama.ptrace_scope=2` sysctl (ssh-keysign-pwn)
3. `~AF_RDS` in the always-on systemd 10-* drop-in (PinTheft)

Plus two new auditd rules:
- `copyfail_afrds` — `AF_RDS=21` socket creation by `auid>=1000`
- `copyfail_pidfd_getfd` — syscall 438 numeric (EL7/EL8 audit-userspace doesn't know the name)

**Naming policy:** `copyfail-defense` stays everywhere. NO `rfxn-` prefix in this release. Audit keys keep `copyfail_*` prefix (new keys are `copyfail_afrds`, `copyfail_pidfd_getfd`). The rename to `rfxn-defense` is deferred to a future major release.

**Tech Stack:** RPM `.spec` (rpmbuild + mock + rpmsign + createrepo_c + gpg), Python 3.6+ stdlib-only (auditor), C99 + libdl (LD_PRELOAD shim, x86_64-only), bash + python3 inline (detect.sh), podman + bash (test harness). Build matrix expands from EL8/9/10 to EL7/8/9/10.

**Phases:** 10

**Plan Version:** 2.1.0-1

- [ ] **Step 1.3: Append `kernel.yama.ptrace_scope` + commented io_uring to `packaging/copyfail-sysctl-userns.conf`**

  Append the following block to the end of the existing file (preserves the existing userns body verbatim):

  ```

  # ssh-keysign-pwn (CVE-2026-46333) primary mitigation.
  # __ptrace_may_access() race exposes root-readable file descriptors
  # (SSH host keys, /etc/shadow) to unprivileged callers via pidfd_getfd
  # on exiting SUID binaries. Yama LSM gates the same permission check,
  # short-circuiting the bug regardless of the mm-NULL fall-through.
  #
  #   0 = unrestricted (RHEL family default - WORST)
  #   1 = parent-child only (Ubuntu/Debian default - PoC bypasses this)
  #   2 = CAP_SYS_PTRACE required (closes the bug; gdb -p as root still works)
  #   3 = ptrace fully off including root (one-way trip until reboot)
  #
  # Default 2: closes pidfd_getfd path without breaking root debugging.
  # Override per-host by dropping a 50-*.conf with a different value.
  -kernel.yama.ptrace_scope            = 2

  # PinTheft (CVE pending) secondary mitigation - io_uring disable.
  # Available on Linux 6.6+ only (EL10+, Ubuntu 24.04+). Disabling
  # io_uring breaks containerd/podman runtimes that use it for I/O.
  # SHIPPED COMMENTED-OUT BY DEFAULT. Operator opt-in: uncomment the
  # next line on hosts confirmed not to require io_uring.
  #
  #   0 = enabled (default)
  #   1 = disabled for new processes
  #   2 = disabled with hard-disable for existing tasks
  #
  #-kernel.io_uring_disabled            = 2
  ```

- [ ] **Step 1.4: Append two new audit rules to `packaging/copyfail-defense-audit.rules`**

  Append (preserving existing 3 rules verbatim — `copyfail_afalg`, `copyfail_afkey`, `copyfail_afrxrpc` stay):

  ```

  ## PinTheft (CVE pending): unprivileged AF_RDS socket creation. RDS is
  ## the entry point for the RDS zerocopy double-free chained to io_uring
  ## fixed buffers. AF_RDS=21 per <linux/socket.h>.
  -a always,exit -F arch=b64 -S socket -F a0=21 -F auid>=1000 -F auid!=-1 -k copyfail_afrds

  ## ssh-keysign-pwn (CVE-2026-46333): unprivileged pidfd_getfd().
  ## Public PoC needs 100-2000 spawns per success; this rule fires loudly
  ## during exploitation attempts. Syscall referenced by NUMERIC value 438
  ## (b64) rather than name 'pidfd_getfd': EL7+EL8 audit-userspace do not
  ## recognise the name. The numeric form parses cleanly on every EL
  ## kernel-userspace combination.
  -a always,exit -F arch=b64 -S 438 -F auid>=1000 -F auid!=-1 -k copyfail_pidfd_getfd
  ```

  After `detect_userns_consumers()`:

  ```bash
  # v2.1.0: PinTheft mitigation gate. RDS modprobe blacklist is suppressed
  # when an Oracle Grid / clusterware / HPC workload is detected. Stock
  # RHEL/Alma/Rocky/Oracle UEK kernels do not ship CONFIG_RDS=m, so the
  # blacklist is a no-op there - we ship it anyway for defense in depth
  # against ELRepo kernel-ml swaps, but suppress on Oracle hosts where
  # rds.ko might be needed.
  detect_rds_workload() {
      # Signal 1: /etc/oratab with non-comment, non-blank entries.
      # Canonical marker for any Oracle product install (Grid, RAC, DB).
      if [ -f /etc/oratab ] && \
         grep -qE '^[[:space:]]*[^#[:space:]]' /etc/oratab 2>/dev/null; then
          RDS_WORKLOAD_PRESENT="true"
          RDS_WORKLOAD_SIGNALS+=("/etc/oratab: non-comment entry present")
      fi

      # Signal 2: Oracle Clusterware control binary. Path conventional but
      # version-dependent; bounded find catches /u01/app/.../grid/bin/crsctl.
      if find /u01/app /opt/oracle -maxdepth 6 -type f \
              -name crsctl -path '*/grid/bin/crsctl' 2>/dev/null | grep -q .; then
          RDS_WORKLOAD_PRESENT="true"
          RDS_WORKLOAD_SIGNALS+=("oracle crsctl present (Grid Infrastructure)")
      fi

      # Signal 3: RDS module already loaded in running kernel - workload
      # in active use. Strong signal regardless of distro.
      local m
      for m in rds rds_tcp rds_rdma; do
          if [ -d "/sys/module/$m" ]; then
              RDS_WORKLOAD_PRESENT="true"
              RDS_WORKLOAD_SIGNALS+=("/sys/module/$m: loaded in running kernel")
          fi
      done

      return 0
  }
  ```
