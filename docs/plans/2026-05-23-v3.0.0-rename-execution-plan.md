**Cron file body** (`packaging/rfxn-defense-autoupdate.cron`):

```
# rfxn-defense — 4-hourly responsive-update cron
# Owned by rfxn-defense-autoupdate. Edit /etc/rfxn-defense/auto-update.disabled
# (touch file) to opt out without removing the package.
#
# Runs at 00:15, 04:15, 08:15, 12:15, 16:15, 20:15 host-local.
# The wrapper jitters 0-600s before doing work to spread mirror load
# across the fleet, then flocks + timeouts + dnf-targeted-upgrades.

SHELL=/bin/bash
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
MAILTO=

15 */4 * * * root /usr/libexec/rfxn-defense/update.sh
```

**Wrapper body** (`packaging/rfxn-defense-update.sh`) — sketch only; engineer drafts the canonical version under TDD:

```bash
#!/bin/bash
# rfxn-defense responsive auto-update wrapper.
# - EL7+ (uses /usr/bin/flock, /usr/bin/timeout, dnf-or-yum auto-detect)
# - opt-out via touch /etc/rfxn-defense/auto-update.disabled
# - jitter 0-600s; flock single-runner; 600s total timeout
# - logs to journald via logger -t rfxn-defense-update
set -euo pipefail

DISABLE_FILE=/etc/rfxn-defense/auto-update.disabled
LOCK_FILE=/run/lock/rfxn-defense-update.lock
LOG_TAG=rfxn-defense-update

[ -f "$DISABLE_FILE" ] && { logger -t "$LOG_TAG" "skip: $DISABLE_FILE present"; exit 0; }

# Single-runner via flock; -n returns immediately if locked
exec 9>"$LOCK_FILE"
if ! flock -n 9; then
  logger -t "$LOG_TAG" "skip: prior run still active"
  exit 0
fi

# Jitter 0-600s
sleep $(awk 'BEGIN{srand(); print int(rand()*600)}')

# Auto-detect dnf vs yum (EL7 ships yum; dnf via EPEL is optional)
if command -v dnf >/dev/null 2>&1; then PKG=dnf; else PKG=yum; fi

logger -t "$LOG_TAG" "begin: $PKG upgrade rfxn-defense*"
timeout 600s "$PKG" -y --disablerepo='*' --enablerepo='rfxn-defense' \
  upgrade 'rfxn-defense*' 2>&1 | logger -t "$LOG_TAG"
rc=${PIPESTATUS[0]}
logger -t "$LOG_TAG" "end: rc=$rc"
exit "$rc"
```

- **Mode:** serial-agent (engineer drafts wrapper under TDD with `bash -n` + shellcheck; cron file is a string drop-in)
- **Accept:**
  - `cmp packaging/RPM-GPG-KEY-rfxn packaging/RPM-GPG-KEY-copyfail` returns rc=0 (byte-identical)
  - `grep -q '\[rfxn-defense\]' packaging/rfxn-defense.repo` rc=0
  - `gpg --import-options show-only --import < packaging/RPM-GPG-KEY-rfxn 2>&1 | grep -q 'D5E80F80'` rc=0
  - `test -f packaging/rfxn-defense-autoupdate.cron && test -f packaging/rfxn-defense-update.sh`
  - `bash -n packaging/rfxn-defense-update.sh`
  - `shellcheck -S warning packaging/rfxn-defense-update.sh` clean (or documented disable comments for unavoidable warnings)
  - `grep -c '15 \*/4 \* \* \*' packaging/rfxn-defense-autoupdate.cron` returns 1 (4-hour cadence at :15)
  - `grep -q 'flock -n' packaging/rfxn-defense-update.sh` rc=0 (lock present)
  - `grep -q 'timeout 600' packaging/rfxn-defense-update.sh` rc=0 (timeout present)
  - `grep -q 'rfxn-defense\*' packaging/rfxn-defense-update.sh` rc=0 (targeted; not whole-system upgrade)
  - `grep -q 'auto-update.disabled' packaging/rfxn-defense-update.sh` rc=0 (opt-out knob)
- **Test:**
  - Wrapper `bash -n` + shellcheck (local)
  - Wrapper executed manually with `--dry-run`-style env override returns rc=0 without touching dnf (engineer adds a `CFD_AUTOUPDATE_DRY_RUN=1` env knob that exits before the `dnf` call for testability)
  - Phase 8 test-repo.sh adds container assertions: cron file present at `/etc/cron.d/rfxn-defense-update`; wrapper executable at `/usr/libexec/rfxn-defense/update.sh`; touch-file opt-out honored
- **Edge cases:**
  - **GPG copy, not symlink** — RPM packaging copies sources into the SRPM tarball; symlink would dereference. Two real files in spec Source list.
  - **EL7 `dnf` availability** — EL7 stock ships `yum`; `dnf` is available via EPEL. Wrapper auto-detects (`command -v dnf || yum`). Both honor `--disablerepo='*' --enablerepo='rfxn-defense'`.
  - **`flock -n` race** — `-n` (non-blocking) is correct: if a prior 4-hour run is still active (slow mirrors, network stall), we want to skip the new attempt, not queue. flock-n's exit code 1 distinguishes "lock held" from "ran and dnf failed".
  - **Logger-only logging** — avoids cron's default mailing (`MAILTO=` empty). Operators tail `journalctl -t rfxn-defense-update`.
  - **No metadata expiration tuning** — we let dnf's default `metadata_expire` (48h) govern when repodata is fetched; the responsive layer doesn't need fresher metadata than dnf already keeps. The 4-hour cadence catches new RPMs as they appear on gh-pages once metadata expires.
  - **EL7 `cron.d` parsing** — EL7 cronie accepts `MAILTO=` empty + the cron line as written. Verified at v2.1.0 EL7 build target.
  - **Jitter window** — 600s = 10 min spread. For a 4-hour cadence this means hosts cluster slightly per slot but no single mirror hit. On a fleet of 1000 hosts: ~167 hosts/minute average load on gh-pages.
- **Regression-case:** wrapper failure cannot crash cron daemon (set -euo pipefail + explicit exit on every path; cron logs failure to journald but next cron tick fires normally).

## Closeout: 2× sentinel + engineer fp + engineer fixup

After Phase 12 PASSes, the dispatcher MUST run the closeout protocol *before* marking the plan complete. This is adversarial double-loop review against the cumulative diff from before Phase 1 to HEAD.

**Sequence (each step waits for prior):**

1. **Sentinel pass 1** — dispatch `rdf-reviewer` (sentinel mode) against the full diff range `main@{before-phase-1}..HEAD`. Output: structured finding list (MUST-FIX / SHOULD-FIX / architectural concern / nits).
2. **Engineer fixup 1** — dispatch `rdf-engineer` with sentinel-1 findings as input. Engineer addresses every MUST-FIX, prioritizes SHOULD-FIX, documents any deferred architectural concerns in `FOLLOWUPS.md`. Commit message prefix: `v3.0.0 sentinel-1 fixup:`.
3. **Sentinel pass 2** — dispatch `rdf-reviewer` (sentinel mode) again against the new HEAD (post-fixup-1). This second pass is the adversarial *re-attack* — does the fix introduce regressions, does it actually close the original finding, are there new issues now visible past the first layer?
4. **Engineer fp pass** — dispatch `rdf-engineer` with sentinel-2 findings + a "full-pass" instruction: re-read all phase commits + sentinel feedback, hunt for cross-cutting consistency gaps (a vocabulary still stuck on `copyfail` somewhere, a `%pretrans` migration path that touches a file Phase 4 didn't refresh, etc.). Commit prefix: `v3.0.0 fp:`.
5. **Engineer fixup 2** — final cleanup of any minor findings the fp pass surfaced. Commit prefix: `v3.0.0 fixup:`. After this commit, the plan is `Status: complete`.

**Mode:** controller-driven serial sequence; the dispatcher does NOT pick this up from a `### Closeout` phase heading — it's invoked by the `/r-build` controller after Phase 12 PASS.

**Accept:**
- 2 sentinel reports written to `.rdf/work-output/sentinel-{1,2}-${RDF_SESSION_ID}.md`
- 2 engineer fixup commits + 1 engineer fp commit landed on `main` (or release branch, then squash-merged)
- Final `git log --oneline main` shows v3.0.0 tag pointing at the last fixup commit
- No MUST-FIX findings remain unaddressed in sentinel-2; any deferred items captured in `FOLLOWUPS.md` under a `v3.1.0 candidates` section

**Test:** the sentinel reports themselves are the gates. If sentinel-2 returns "no MUST-FIX, all fixup acknowledged", closeout PASSes.
