Defense-in-depth toolkit for two bug classes: the Copy Fail class (five live LPE chains sharing the splice() → MSG_SPLICE_PAGES page-cache write primitive) and the FD-theft class (privilege-confusion via SUID exit-race, first member: ssh-keysign-pwn).

cf2 / Dirty Frag-ESP CVE-2026-43284 esp_input skip_cow path CAP_NET_ADMIN via unshare(NEWUSER|NEWNET) + SA install via AF_KEY / XFRM netlink
Dirty Frag-RxRPC CVE-2026-43500 rxkad_verify_packet_1 in-place pcbc(fcrypt) none
Fragnesia (no CVE yet; same surface as CVE-2026-43284) espintcp ULP after splice into TCP receive queue same as cf2
PinTheft (v2.1.0) (CVE pending; disclosed 2026-05) RDS zerocopy double-free chained to io_uring fixed-buffer page-cache overwrite of SUID-root binary none on kernels with CONFIG_RDS=m (Ubuntu/Debian/Arch stock; RHEL+ELRepo kernel-ml swap)
ssh-keysign-pwn (v2.1.0; FD-theft class) CVE-2026-46333 __ptrace_may_access() race exposes root-readable FDs (SSH host keys, /etc/shadow) via pidfd_getfd on exiting SUID binary none

Six defense-in-depth rungs in one dnf install for EL7/EL8/EL9/EL10: LD_PRELOAD shim, modprobe blacklist, per-unit systemd drop-ins, host-wide userns + ptrace sysctl, auditd tripwires, and a read-only posture auditor. Auto-detection at install time suppresses any drop-in that would conflict with detected workloads (IPsec, AFS, rootless containers, Flatpak, firejail, desktop browsers, Oracle RDS / HPC); every other layer stays active.

See the Changelog for per-version detail, Auto-detection for the signal list and suppression matrix, and rfxn.com/research for the cf1 kernel mechanics deep-dive.

Upgrading from any 2.0.x / 2.1.x or afalg-defense v1.0.x? dnf upgrade copyfail-defense handles every prior layout change (rename, file split, new subpackages) automatically. Auto-detect re-runs on each upgrade; review journalctl -t copyfail-defense afterward to see what was suppressed. Shim activation remains the explicit operator step (copyfail-shim-enable).
EL7 (CentOS 7 / RHEL 7) support — v2.1.0. CentOS 7 reached EOL 2024-06-30. v2.1.0 RPMs are built against vault.centos.org/centos/7.9.2009/ via a custom mock chroot and signed with the same project key as EL8/9/10. The auditor's pidfd_getfd auditd rule uses the numeric syscall form (-S 438) because EL7+EL8 audit-userspace do not recognise the name string; auditctl accepts the numeric form cleanly on every EL kernel-userspace combination.

Install

A single copyfail.repo file works for EL7/EL8/EL9/EL10: dnf expands $releasever + $basearch per host. RPMs are GPG-signed and the metadata itself is verified via detached repomd.xml.asc (gpgcheck=1 + repo_gpgcheck=1). 

sudo curl -sSL https://rfxn.github.io/copyfail/copyfail.repo \
  -o /etc/yum.repos.d/copyfail.repo
sudo dnf install -y copyfail-defense
sudo /usr/sbin/copyfail-shim-enable

The meta pulls six subpackages (-audit as soft dep on EL8/9/10, hard dep on EL7 since rpm-4.11 has no Recommends: mechanism):

copyfail-defense-systemd per-unit RestrictAddressFamilies=~AF_ALG ~AF_KEY ~AF_RXRPC ~AF_RDS (~AF_RDS added v2.1.0 for PinTheft) + RestrictNamespaces=~user ~net on user@/sshd/cron/crond/atd + opt-in container-runtime examples + RDS opt-in template (v2.1.0)

Changelog

Per-version summary. Full per-commit history: github.com/rfxn/copyfail/commits. Per-release notes: github.com/rfxn/copyfail/releases.

v2.1.0 (2026-05-22) · PinTheft + ssh-keysign-pwn + EL7 build target

  • PinTheft (CVE pending) — Copy Fail class extension. New /etc/modprobe.d/99-copyfail-defense-rds.conf blocks rds / rds_tcp / rds_rdma module load; ~AF_RDS added to the always-on 10-* systemd drop-in on all 5 tenant units; new copyfail_afrds auditd rule fires on socket(AF_RDS=21) from auid≥1000.
  • ssh-keysign-pwn (CVE-2026-46333) — FD-theft class, first member. New kernel.yama.ptrace_scope=2 sysctl key in 99-copyfail-defense-userns.conf closes the pidfd_getfd path without breaking root debugging; new copyfail_pidfd_getfd auditd rule on syscall 438 (numeric form — EL7+EL8 audit-userspace do not recognise the name string).
  • Operator opt-in commented-out kernel.io_uring_disabled=2 (PinTheft secondary mitigation; Linux 6.6+ only). Disabling io_uring breaks containerd/podman runtimes that depend on it — opt in per host.
  • Auto-detect gains detect_rds_workload(): signals /etc/oratab non-comment entry, Oracle crsctl binary, or rds*.ko loaded in the running kernel. Suppresses the rds modprobe blacklist on Oracle Grid / HPC hosts.
  • Auditor extends from 4 to 6 bug classes: cf1 / cf2 / dirtyfrag-esp / dirtyfrag-rxrpc / pintheft / keysign-pwn. Four new checks for ptrace_scope, AF_RDS restrict, rds modprobe, pidfd_getfd auditd rule. JSON state schema_version stays "2" (additive, backward compatible).
  • EL7 build target added. RPMs built against vault.centos.org/centos/7.9.2009/ via custom mock chroot config; same signing key as EL8/9/10. EL7's rpm-4.11 lacks the Recommends: tag — -audit is a hard Requires: there.
  • Operator-facing changes: README, gh-pages landing, STATE.md / BRIEF.md / SPEC.md updated with PinTheft + ssh-keysign-pwn rows and the EL7 vault note. v2.0.x RPMs retained in the gh-pages repodata so dnf upgrade from any prior version resolves cleanly.

v2.0.2 (2026-05-13) · Fragnesia / Dirty Frag-ESP coverage

  • New copyfail-defense-sysctl: host-wide user.max_user_namespaces=0 sysctl drop-in. Auto-suppressed on rootless containers, Flatpak, firejail, desktop browsers.
  • New copyfail-defense-audit (soft-dep): auditd rules tripping on socket(AF_ALG/AF_KEY/AF_RXRPC) at auid≥1000. Query: ausearch -k copyfail_afalg|copyfail_afkey|copyfail_afrxrpc.
  • systemd 10-* drop-in adds ~AF_KEY to RestrictAddressFamilies. Closes the PF_KEYv2 SA-config path used by Dirty Frag / Fragnesia.
  • CVE cross-stamping: cf2 = CVE-2026-43284, DF-RxRPC = CVE-2026-43500. Fragnesia documented as same surface as CVE-2026-43284 (no upstream CVE assigned yet).

v2.0.1-2 (2026-05-08) · packaging hotfix

  • -p /bin/bash on four proc-sub scriptlets (%posttrans / %postun for -modprobe and -systemd). Without it, EL8's /bin/sh rejects the bash proc-sub idiom as a syntax error and detect.sh silently never runs.
  • %pretrans v2.0.0→v2.0.1 rename guard fixed: was using unescaped %{version} (expanded at build time); now uses %%{version} so the macro reaches the scriptlet body and queries the actually-installed version.
  • test-repo.sh adds a scriptlet-failure regression guard that catches the class of bug 2.0.1-1 shipped with (scriptlet failed / syntax error near markers in dnf output).

v2.0.1 (2026-05-08) · workload auto-detection

  • %posttrans detection of IPsec / AFS / rootless-container workloads. Conflicting drop-ins are suppressed automatically; every other layer stays active. State written to /var/lib/copyfail-defense/auto-detect.json.
  • File-layout split: monolithic modprobe + systemd drop files become three modprobe files (-cf1, -cf2-xfrm, -rxrpc) and three systemd drop-in layers (10-* always-on, 12-* AF_RXRPC, 15-* userns).
  • New copyfail-redetect helper re-runs detection on demand. /etc/copyfail/force-full sentinel bypasses detection.

v2.0.0 (2026-05-08) · copyfail-defense umbrella

  • Package family renamed afalg-defense → copyfail-defense. Scope expanded to the Copy Fail bug class (cf1 + cf2 + Dirty Frag).
  • New -modprobe subpackage: kernel-module entry-point cuts.
  • New -systemd subpackage: per-unit RestrictAddressFamilies and RestrictNamespaces drop-ins on user@/sshd/cron/crond/atd.
  • Obsoletes:/Provides: on afalg-defense* for clean upgrade. Compat retained through the 2.0.x line.

Auto-detection of conflicting workloads

v2.0.1+ inspects the host in %posttrans for workloads the default cuts would break, and suppresses the conflicting drop-in only while every other layer stays active. The intent is "do no harm to running production"; nothing else relaxes. The cf1 LD_PRELOAD shim and the auditor are never suppressed, so CVE-2026-31431 coverage is unchanged on every host.

Why each workload triggers a carve-out

WorkloadWhy the default would break it
IPsec (strongSwan, libreswan, openswan) The kernel xfrm/esp path is the cf2 / Dirty Frag-ESP kernel sink. Blacklisting esp4/esp6/xfrm_user/xfrm_algo disables IPsec tunnels entirely (no SA install, no encrypted traffic). Suppression keeps the modprobe drop off and leans on systemd RestrictNamespaces=~user ~net to block the unshare(NEWUSER|NEWNET) step that gates cf2.
AFS (openafs, kafs) rxrpc is both the DF-RxRPC kernel sink and the transport AFS itself rides on; blacklisting it breaks openafs-client. The per-unit RestrictAddressFamilies=~AF_RXRPC would also break AFS userspace tooling (aklog, kinit-style PAGs) when invoked from any of the five tenant units.
Rootless containers (rootless podman/buildah) Rootless podman/buildah needs CLONE_NEWUSER under the calling user@.service. Our default RestrictNamespaces=~user ~net on user@.service turns the unshare(2) into EPERM, which kills every rootless container. Suppression strips the userns drop-in on user@.service only: sshd/cron/crond/atd retain it.
RDS workload (Oracle Grid Infrastructure, HPC; v2.1.0) Oracle clusterware / RAC and certain HPC stacks legitimately use AF_RDS sockets. Blacklisting rds / rds_tcp / rds_rdma would prevent the module from loading and break those workloads. Suppression removes only the rds modprobe drop; the always-on ~AF_RDS systemd restriction on tenant units still applies (tenant units do not legitimately speak RDS), and the copyfail_afrds auditd rule still fires — so unprivileged AF_RDS use from a non-Oracle process remains visible.

False-positive guards baked into the detector: /etc/subuid populated by useradd is not a rootless signal: shadow-utils auto-populates subuid for every regular user regardless of container intent, which produced near-100% FPs on cPanel-shaped fleets in v2.0.1 rev 1. The rootful /var/lib/containers/storage signal is gated on mtime < 90d so a long-purged podman install doesn't keep triggering suppression. The /home walk is bounded (maxdepth 6, mtime -180) so a pathological tenant home tree can't stall %posttrans. The /run/user/<UID>/containers signal requires UID ≥ 1000 so system-account artifacts under /run/user/0 don't trip detection.

Override paths

The default install applies RestrictNamespaces=~user ~net to user@.service. This breaks rootless podman/buildah under user@.service. Override: 

sudo install -d /etc/systemd/system/user@.service.d
sudo tee /etc/systemd/system/user@.service.d/20-override.conf >/dev/null <<'EOF'
[Service]
RestrictNamespaces=
RestrictAddressFamilies=
EOF
sudo systemctl daemon-reload

The 10- prefix on package drop-ins and 99- prefix on the modprobe drop are deliberate: any 20-*.conf or numerically-later operator file overrides ours.

If your fleet legitimately uses IPsec (strongSwan, libreswan, FRRouting), the modprobe blacklist breaks those workloads. Either skip the modprobe subpackage: 

sudo dnf install copyfail-defense-shim copyfail-defense-systemd copyfail-defense-auditor
# (omit copyfail-defense and copyfail-defense-modprobe)

…or remove the relevant entries from /etc/modprobe.d/99-copyfail-defense.conf (the file is %config(noreplace), so your edit survives package upgrade). Same logic for AFS (openafs, kafs) and the rxrpc blacklist line.

Direct downloads

Each release on github.com/rfxn/copyfail/releases ships per-EL binary RPMs, an SRPM, the .repo file, and the public signing key as release assets. Only the current version is listed below; prior 2.0.x releases and the legacy afalg-defense 1.0.1 line remain in the dnf repodata so dnf upgrade resolves cleanly from any installed version. Pin a specific older release with dnf install copyfail-defense-2.0.1* if needed, or browse all of them on the GitHub releases page.

The .repo file (works on EL7/EL8/EL9/EL10):

sudo curl -sSL https://rfxn.github.io/copyfail/copyfail.repo \
  -o /etc/yum.repos.d/copyfail.repo

And the public signing key (dnf imports this automatically on first install, but you can pre-import it):

sudo curl -sSL https://rfxn.github.io/copyfail/RPM-GPG-KEY-copyfail \
  | sudo rpm --import /dev/stdin

Per-EL binary RPMs are independently compiled against each distribution's glibc (EL7: 2.17 with split libdl; EL8: 2.28 with split libdl; EL9/EL10: 2.34+ with merged libdl); do not cross-install across ELs. v2.1.0 is the current line; v2.0.2 RPMs remain in the dnf repodata for legacy upgrade-path testing.

Defense in depth

Each rung defeats the bug by a different mechanism, so an attack that defeats one does not necessarily defeat the next.

RungWhere it failsWhat the next rung covers
Kernel patch (vendor) EL7 reached EOL 2024-06-30 (no vendor patches for new CVEs); rollout on supported ELs lags disclosure days-to-weeks; reboot may not be available; Dirty Frag-RxRPC has no upstream patch; Fragnesia is on netdev only as of 2026-05-13, not yet in stable trees; PinTheft and ssh-keysign-pwn (CVE-2026-46333) are pre-upstream as of 2026-05 Userspace cuts close the window without a reboot — the entire copyfail-defense rung set is a kernel-patch-free coverage path
modprobe blacklist No-op when relevant module is builtin (RHEL algif_aead is); no effect on already-resident modules Functional for esp4/esp6/xfrm_user/xfrm_algo/rxrpc on stock RHEL kernels. RHEL algif_aead: use grubby --update-kernel ALL --args "initcall_blacklist=algif_aead_init" + reboot.
systemd RestrictAddressFamilies / RestrictNamespaces Reaches only services systemd starts post-restriction. Misses cron-as-root, sshd-pre-restriction, container payloads with own pid 1, interactive shell users running an exploit binary Host-wide userns sysctl (v2.0.2) catches the interactive-shell case; LD_PRELOAD shim covers every dyn-linked process regardless of init
Host-wide userns sysctl (v2.0.2) Auto-suppressed on rootless containers / Flatpak / firejail / desktop browsers. Setting only affects unshare(2) calls made after the sysctl took effect; in-flight processes that already grabbed a userns retain it until exit Per-unit RestrictNamespaces still applies on the five tenant units even when the host-wide sysctl is suppressed; auditd rules log post-suppression userns prep
LD_PRELOAD shim Static binaries; direct syscall instruction; SUID strip seccomp at unit/runtime level catches direct-syscall path
seccomp filter Per-service. Operationally heavy: each unit/runtime needs explicit policy This package's systemd subpackage ships a one-line filter for the highest-leverage tenant units
auditd tripwire rules (v2.0.2) Detection only, not mitigation. Fails when auditd is not running, the rules are unloaded, or the attacker arrives via a path that bypasses syscall auditing (kprobe-disabled kernels) Becomes the residual signal on hosts where modprobe blacklists are auto-suppressed (IPsec / AFS workloads) and the kernel sink stays reachable
